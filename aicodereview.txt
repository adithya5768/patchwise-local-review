[bounds checking and write atomicity] Missing bounds check for offset+size
against rmb_node->len before memcpy. Unbounded offsets allow writes past
the allocated buffer, causing memory corruption. Validate that offset +
size <= rmb_node->len before copying data.

> +	read_unlock_bh(&ldev->dmb_ht_lock);

[lock granularity and hot-path performance] Excessive lock hold time during
memcpy. read_lock_bh covers hash lookup, memcpy, and unlock, blocking
writers and risking starvation. Copy token and sba_idx to local variables,
release the lock, then perform the memcpy outside the critical section.

> +

> +		conn = smcd->conn[rmb_node->sba_idx];
> +		if (conn && !conn->killed)

[concurrency and node lifetime management] Use-after-free race in
smc_lo_move_data. The code dereferences rmb_node after dropping
read_lock_bh. Between unlocking and accessing rmb_node,
smc_lo_unregister_dmb can free the node. Hold a reference (e.g., RCU or
refcount) to extend its lifetime, or read sba_idx before releasing the
lock.


[connection notification and tasklet scheduling] Unprotected access to
smcd->conn[] array. The connection pointer is read without holding
smcd->lock, risking stale or freed memory access. Hold smcd->lock during
connection array reads, following the pattern used in smc_ism.c.

> +		else

[connection notification and tasklet scheduling] Race on conn->killed check
without lock protection. The connection can be freed between the null check
and tasklet_schedule. Hold smcd->lock during the entire connection access
and tasklet scheduling sequence to prevent use-after-free.
